# 补丁全量插件化 + 正常升级方案

**目标**：把 `F:\DSH\dsh-runtime`（@deepseek-ai/dsh 0.1.2-rc.1，约 35 处对官方包编译产物的直接 patch）升级到 0.1.5-rc.1，并将全部修改重建为 dsh 插件。此后"正常升级"= 改版本号 + `npm install`，插件不受影响。`~/.dsh`（设置/会话/插件）与 `图层-0.ico` 全程不动。

## 第 0 步：安全网
1. `robocopy` 全量镜像 `F:\DSH\dsh-runtime` → `F:\DSH\backup-dsh-runtime-0.1.2-rc.1`。
2. 在运行时目录 `git init`（autocrlf=false）全量提交，作为可回滚锚点。

## 第 1 步：补丁清单与语义分类
3. 建迁移工作区 `F:\DSH\dsh-migration\`；`npm pack` 受影响包的 **0.1.2-rc.1** 与 **0.1.5-rc.1** tarball 作为双基线。
4. 44 个 mtime 候选文件逐一 diff（vs 0.1.2 原版）：相同→排除（mtime 波及）；不同→生成 diff 并写明语义，产出 `patches-inventory.md`，含 `.bak-20260908` 交叉验证与 web-frontend bundle 补丁的语义还原。
5. 每项补丁归入三类：
   - **A 类·接缝原生**（ctx.settings 分区、ctx.llm 适配器、client 插件图、UI slots、工具/命令注册）→ 标准插件；
   - **B 类·接缝外**（官方包内部行为，如 conversation timeline healing、models 页行级探测）→ **shim 插件**：加载时对目标运行时对象 wrap/patch + 结构自检（不匹配即显式报错，杜绝静默失效）；
   - **C 类·可废弃**（0.1.5 已原生实现同等功能）→ 直接废弃，清单中注明。
6. 对照 0.1.5 实际代码核对分类（插件 API 以 0.1.5 为准），与清单一起留档。

## 第 2 步：干净升级运行时
7. `package.json` → `@deepseek-ai/dsh@^0.1.5-rc.1`（移除遗留 `_npx` 字段），`npm install`，`dsh --version` + `dsh web --no-open` 冒烟。

## 第 3 步：插件化重建（核心工作量）
8. 插件统一定位 `~/.dsh/profiles/web/plugins/`（与现有 notification-sounds 同层），每个插件独立 package.json：host face `lib/index.js` + client face `lib/client.js`（`dsh.client` 声明）。
9. 按 inventory 逐项实现：
   - A 类走官方注册面（settings 分区、llm 适配器、slots 等）；
   - B 类 shim 插件先断言目标内部结构再修补，版本不符时报错并指向 inventory 对应条目；
   - 每完成一项，对照原补丁行为做功能验证（重点：conversation healing、模型探测、llm-deepseek Files API fallback、theme 定制）。
10. 一并补全 notification-sounds 缺失的 `lib/client.js`。
11. 若个别补丁经实测既无法 A 类表达、shim 又不可靠（预计极少），保留为唯一 patch-package 补丁并向你单独说明取舍——这是唯一的例外通道。

## 第 4 步：收尾
12. 重写 `RUNTIME-README.md`：正常升级流程（npm install 即可，插件/数据在外部不受影响）+ 插件清单与原补丁映射表。
13. git 最终提交；冒烟回归。

## 风险与说明
- 最大不确定点是 minified web-frontend bundle 补丁的语义还原，若 diff 无法自解释会向你确认意图后再实现。
- B 类 shim 在上游内部重构时会响亮失败（设计如此），届时按映射表适配即可，不会再发生静默丢失。
- 需要 npm 网络访问（拉 0.1.2/0.1.5 tarball 与安装）。
